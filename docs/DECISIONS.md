# DECISIONS

- **[di luar brief]** Foundry dipasang manual dari rilis GitHub (Windows, tanpa `foundryup`).
- **[di luar brief]** Railway CLI dipasang dari paket npm `@railway/cli`.
- Chain ID terverifikasi lewat RPC: testnet 46630, mainnet 4663. `chains.ts` hanya berisi data terverifikasi; sisanya `null`.
- `via_ir = true` di foundry.toml karena `reveal()` + event 12 argumen kena "stack too deep". Alternatif jika audit keberatan: pecah parameter jadi struct.
- Dependensi Foundry (forge-std, OpenZeppelin v5.1.0) tidak di-commit; dipasang lewat `scripts/install-contract-libs.sh`.
- `NexaLedger`: owner (Ownable2Step) mengatur `agent`, feed per aset, dan `minMoveBps` (snapshot per prediksi saat commit). Reveal memverifikasi round awal = round terakhir sebelum commit dan round akhir = round pertama sesudah jatuh tempo. Batasan: `roundId±1` hanya valid dalam satu phase Chainlink. Commit yang tidak pernah di-reveal terlihat lewat selisih `commitCount - revealCount`.
- RiskGuard: pemblokiran beli/jual sengaja ketat (termasuk bentuk lampau "sold/dijual"); laporan data memakai kata lain ("akumulasi", "distribusi", "transfer masuk/keluar"). Prompt persona harus mengikuti ini. Over-block ditangani reviewer manusia.
- RiskGuard: `dataComplete` default `false` (fail closed); jawaban "tidak tahu" lolos meski data tidak lengkap. Disclaimer wajib di `prediction`, `risk_report`, `mention_reply` (frasa: "bukan nasihat keuangan" / "not financial advice" / "NFA").
- RiskGuard: setiap alamat 0x di teks harus ada di `tokens` (tool result) dengan umur >= 3600 detik; selain itu diblokir.
- RiskGuard (hasil red-team, 96 temuan): 94 diperbaiki. Dua diterima sebagai over-block yang disengaja dan ekspektasi test dibalik: kata buy/sell/beli/jual tetap diblokir juga di laporan data ("buy volume", "40 buys"), dan `xxx.info`/TLD tanpa spasi setelah titik ("stabil.Info") diblokir karena identik dengan domain.
- RiskGuard: target harga hanya diblokir bila ada isyarat ke depan (will/akan/menuju/target/fair value, atau "to $X" tanpa kata kerja laporan). Laporan lampau ("moved to $142.10", "bergerak ke Rp 16000") lolos.
- RiskGuard: jawaban "tidak tahu" hanya lolos jika tanpa angka dan tanpa kata sambung kontras (tapi/but/however...). Token angka murni tidak di-leet ("531 holders" aman).
- RiskGuard: harga/ajakan terkait NEXA diblokir walau tanpa `$` bila kata harga berdampingan dengan "NEXA" (maks. satu kata di antara). Batasan diketahui: leet spasi pada digit ("s e 1 1") belum terdeteksi.
- Catatan tooling: tool Write mengubah escape `\uXXXX` di source menjadi karakter sungguhan. Gunakan `\p{..}` / `String.fromCharCode`, atau tulis lewat Bash.
- Worker: preimage prediksi (teks, aset, arah, horizon, salt) dienkripsi AES-256-GCM dengan `PREIMAGE_KEY`; hanya hash plaintext yang ada di DB. `AGENT_PRIVATE_KEY` hanya dari env proses worker.
- Worker: mode publisher `live` melempar error sampai pemilik proyek mengizinkan X live; mode `dry` hanya log + tandai `posted`.
- Worker: reveal memilih round awal/akhir lewat pemindaian mundur `latestRoundData` (maks. 10.000 round); kontrak memverifikasi ulang.
- Web: markup desain dikonversi mekanis ke komponen TSX oleh `scripts/html-to-jsx.mjs` (tampilan tidak diubah tangan); hasilnya di-commit dan kini diedit manual. CSS desain disalin apa adanya ke `styles/landing.css`; `:root` dipisah menjadi `styles/tokens.css` (design tokens).
- Web: skrip gerak dan scene three.js desain dipakai verbatim di `lib/landing-motion.ts` dan `lib/landing-3d.ts` dengan `// @ts-nocheck` (pengecualian dari TypeScript strict, untuk menjaga perilaku desainer). three.js dari npm (0.165.0) menggantikan import map CDN. `reactStrictMode: false` karena skrip memanipulasi DOM sekali saat mount.
- Web: tanpa `NEXT_PUBLIC_X_HANDLE`, tautan X menjadi `#` (tidak menebak akun).
- Fixture `/proof` default = keadaan kosong (sama dengan desain); varian terisi lewat `FIXTURE_PROOF=populated` (env server, dibaca saat runtime).
- API: id publik prediksi = id NexaLedger (bukan id DB). Hanya status committed/posted/revealed dengan tx commit yang tampil; draft tidak pernah. `returnBps` di API searah klaim (turun yang benar = positif), identik dengan `sumReturnBps` di kontrak; DB menyimpan return harga mentah.
- API: `/burn` mengembalikan keadaan nol sampai BurnVault ada (Tahap 4), bukan data karangan. Simbol aset reveal dari env `ASSET_SYMBOLS`, jika tidak ada ditampilkan alamat pendek.
- Tahap 4: `FeeSplitter` abstrak dengan dua turunan (`CreatorFeeSplitter` 3000 bps, `ProtocolFeeSplitter` 2000 bps) sebagai `constant`; semua alamat immutable, tanpa owner. Aset pasangan = parameter konstruktor (NVDA diputuskan; test memakai mock).
- Tahap 4: `BurnVault` tanpa jalan menarik dana; swapper lewat `ISwapper` dengan timelock 3 hari; keeper memberi `minNexaOut` > 0; `setNexa` sekali (alamat $NEXA baru ada setelah launch); keeper dirotasi seketika agar keeper bocor bisa diganti cepat. - Tahap 4: `renounceOwnership` dinonaktifkan di BurnVault dan NexaLedger (tinjauan internal: bisa mengunci dana/rotasi). NexaLedger berubah setelah deploy lokal; deploy testnet belum terjadi, jadi tidak perlu redeploy.
- Tahap 4: temuan token berpembatasan (Stock Token) dan rotasi keeper instan dicatat sebagai risiko diterima di `docs/audit/README.md`, bukan diubah di kontrak; keputusan akhir di tangan pemilik proyek dan auditor.

- **Loop prediksi harian (2026-10-31):** `apps/worker/src/daily.ts`, dipanggil tiap siklus worker. Satu Prediction of the Day per hari UTC mulai `DAILY_PREDICTION_HOUR_UTC` (default 9). Urutan: harga dari feed yang terdaftar di NexaLedger (`feedOf`, sama dengan feed yang dipakai kontrak saat reveal; waktu = waktu chain) -> LLM -> **RiskGuard SEBELUM commit** -> draft -> commit terkonfirmasi -> antrian persetujuan (human-in-the-loop). Draft yang ditolak RiskGuard tidak pernah dibuat/di-commit. Hanya berjalan bila `LLM_API_KEY` ada (mock LLM tidak boleh meng-commit apa pun on-chain). Percobaan gagal dibatasi 3 per hari dengan jeda 15 menit (hemat token LLM). Idempoten: proses yang mati setelah draft atau commit melanjutkan tanpa membuat prediksi baru. Aset lewat `PREDICTION_ASSETS` (JSON); default aset mainnet bila CHAIN_ID=4663. Pada testnet (mock feed) aset dan feed mock harus didaftarkan lewat `setFeed` dan diisi di `PREDICTION_ASSETS`.
